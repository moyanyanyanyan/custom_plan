## 已确认边界

- 每轮用户交流与 AI 回复结束后提炼一次，不逐条消息生成记忆，也不等待整段会话结束。
- 每个角色只使用自己的记忆，不提供共享功能。
- 用户不能手动删除相关记忆；事实澄清仍可推动系统修正误解。
- 核心设定不受聊天改写；非核心部分可以随相处显著成长。
- 经历逐渐模糊并遗忘，对用户的认知和形成的性格不随经历一起自动清空。
- 长期不交流可以生疏，但不因缺席自动产生怨恨。

## 状态与经历的分工

| 类别 | 主要归属 | 变化方式 |
|---|---|---|
| 核心人设、世界基本规则 | 角色配置 | 用户在角色设置修改 |
| 非核心性格、世界认识 | 业务数据库角色状态 | 证据驱动的成长 |
| 用户认知 | 业务数据库角色状态 | 明确事实、推测、纠正分开处理 |
| 情绪、关系、未解决事项 | 业务数据库角色状态 | 本轮影响与时间变化 |
| 经历与概括 | Claude-Mem 及其数据库 | 提炼、合并、检索、自然遗忘 |
| 来源、版本、已应用事件、生命周期 | 应用业务数据库 | 后端维护一致性 |

Claude-Mem 不是模型训练，也不直接负责决定性格和关系。模型提出建议，应用校验后更新；是否固定取决于类别与权限，不取决于是不是数据库字段。

## 更新共同约束（建议方案）

- 状态绑定 characterId，服务端检查归属。
- 每次变化带来源轮次、事件 ID、前后版本、原因与证据。
- 同一事件只应用一次；检索和压缩不得重复产生关系影响。
- 回复前临时态度与回复后持久化属于同一轮，需要统一协议。
- 核心写入口与自动更新路径分离，后台没有核心设定修改权限。
- 更新失败可恢复，不将记忆索引与业务状态的部分成功误报为整体完成。
- 参数均标为待校准，不能直接将此前对话中的数字作为已确认要求。
