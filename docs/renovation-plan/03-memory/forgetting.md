# 自然遗忘与生命周期

[记忆目录](README.md)

## 已确认

- 用户不能手动删除相关记忆，也没有删除经历或撤销经历影响的入口与接口。
- 自然遗忘主要作用于经历：先模糊具体细节，再遗忘。
- 非核心性格、世界认识、对用户的认知和关系不随经历一起自动清空。
- 短期情绪平复属于状态变化；长期缺席生疏属于关系变化，不混同经历遗忘。

## 建议生命周期

```text
清晰经历 → 保留意义的概括 → 退出可检索记忆
```

综合年代、重要性、重复程度、真实重访、未解决事项决定顺序，不简单删最旧的一条。重要转折保留较久，未解决事项和有效约定暂缓遗忘。

- 合并概括保留时间范围，不能把多次事件捏造成一次。
- 模型或系统自行检索不刷新“真实重访”时间。
- 退出记忆后移除相关内容和索引，登记来源排除，阻止后台重新提炼。
- 原始聊天可继续供用户查看，但不能自动全量重扫来补回已遗忘细节。
- 摘要、缓存、并发任务和恢复备份也必须遵守排除规则，不能只删除一张索引表。
- 成长、认知和关系可以保留已形成的结果，但没有细节依据时不能捏造原话或日期。
- 新信息可以推翻误解。“不能删除”不能导致错误认知永久不可修正。

## 建议参数，未确认

普通经历 30 天后压缩、再过 90 天考虑遗忘、重要转折延长 3 倍等均为此前示例，不是现行确定规则。需要先确定重要性分级和容量目标，再确定周期。

## 待定 M-06

- 重要性算法、淡化周期、容量触发、约定完成后的衰减。
- 用户明确要求回顾旧原文是否允许当前轮使用、是否重建经历，以及与自然遗忘的边界。
- 经历细节消失后，如何保留最低限度的关系依据又不让它变成暗藏的完整记忆。
- 已遗忘事件后来被澄清，如何找到受影响判断并修正。
- 角色设置中的核心修改、整个角色生命周期与自然遗忘怎样区分，不能推断已有清空权限。

## 验收

检索不无限续期；自然遗忘不会撤回成长；摘要和旧任务不会恢复已遗忘内容；界面没有用户删除能力；缺少细节时允许承认记不清，不编造。
