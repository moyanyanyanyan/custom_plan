# 即时情绪、变化与表达

[记忆目录](README.md)

## 设计方向

用户要求细化“存什么情绪、怎样根据回复变化”，以下为已讨论的建议机制。具体类别、数字和参数尚未确认，不属于心理测量结论。

情绪、长期关系、外在表达分别管理。角色可以在意用户却语气克制，也可以平静且不感兴趣；不能强行解释为冷淡背后一定亲近。

## 建议情绪类别

| 类别 | 例子 | 可能来源 |
|---|---|---|
| 愉悦 | 满足、欣慰 | 目标完成、有趣交流 |
| 兴趣 | 好奇、期待 | 新资料、感兴趣的话题 |
| 温情 | 怜惜、在意、靠近 | 真诚交流、被理解 |
| 不悦 | 被打扰、边界受侵犯 | 重复打断、贬低、越界 |
| 失望 | 预期落空 | 重要承诺未兑现 |
| 难过 | 低落、失落 | 重要损失或关系事件 |
| 担忧 | 对可能结果的顾虑 | 用户困难、明确的风险语境 |
| 窘迫 | 不自在、难以面对 | 意外夸奖、被指出矛盾 |

允许多种同时存在。冷静属于性格／稳定性，冷淡属于表达，信任属于关系，不都塞进情绪列表。

## 存储草案

- 当前状态：角色 ID、版本、更新时间、情绪类型、强度、触发事件、情绪指向对象。
- 更新依据：轮次、事件解释、确定程度、来源消息、前后值、已应用事件 ID。
- 角色参数：关注点、敏感程度、情绪惯性、平复速度、表达克制程度。
- 未解决事项单独记录，不靠持续维持愤怒表示问题未解决。

强度可暂用 0～100；它是内部状态量，不是实际测出的心理值。查看页是否展示数字待定。

## 每轮变化

```text
用户消息＋语境
→ 识别事件、玩笑／引用／边界／冒犯等解释
→ 对照角色关注点、预期、关系及确定程度
→ 形成临时情绪与表达意图
→ 生成回复
→ 后台核对并持久化同一次变化
```

模型判断语义并提出建议，代码限制范围、版本、幂等和核心约束。存在歧义时小幅或不更新，必要时询问，不能负面关键词一出现就固定生气。

| 用户表达 | 结合语境的理解 | 建议变化 |
|---|---|---|
| 你怎么这么烦 | 可能嫌提醒过多 | 轻微不悦，暂不概括用户人格 |
| 我在开会，刚才着急 | 新信息解释此前措辞 | 修正理解，不悦下降 |
| 以后我说忙就先别提醒 | 明确交流偏好 | 更新认知，不必新增负面情绪 |
| 谢谢，你也是担心我 | 对意图的认可 | 按性格与关系产生温情或愉悦 |

## 时间变化

建议读取状态时按真实经过时间计算，无需每秒写数据库。概念公式：

```text
新强度 = 向角色基线平复后的旧强度 + 本轮影响
剩余偏离 = 原偏离 × 0.5^(经过时间 / 半衰期)
```

不同情绪、事件和角色使用不同参数。普通事件小幅变化，重大事件必须有可靠依据。失望消退不等于承诺问题已解决。

## 表达设计

表达参考性格、关系、情绪与本轮目的，决定直接程度、温度、篇幅、主动性、是否披露感受。无需独立调用多个模型，可与聊天在一次调用完成。

冷静角色可以表达“知道了。我先不提醒。需要时叫我。”；不能统一套入委屈求安慰。角色生成的亲密台词不能反过来作为关系升级证据。

## 待定 M-04

- 最终类别、稀疏或全量状态、基线、各类平复与影响上限。
- 前台临时情绪的结构化输出如何与流式文本共存；不输出模型完整思考过程。
- 后台建议与前台不一致时如何校正、哪些临时状态要保存。
- 快速下一轮和多端并发的状态顺序；同一轮最多应用一次影响。
- 关系和情绪的内部数值是否向用户展示。

## 验收

同一句话在不同语境产生合理差异；澄清可减少不悦；检索旧经历不重复扣状态；自身回复不能成为独立外部证据；冷静不等于无情绪，语气克制不等于隐藏爱意。
