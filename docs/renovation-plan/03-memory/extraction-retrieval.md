# 每轮提炼与按需检索

[记忆目录](README.md)

## 已确认

一轮用户消息与角色回复结束后检查一次。可以不新增记忆，也可以提取多个主题、合并重复经历或纠正已有理解，不建立“每条消息必须对应一条记忆”的关系。

## 建议写入流程

1. 可靠保存用户消息和实际回复，登记 turnId 与处理版本。
2. 同一角色按顺序读取本轮、相关前文、摘要及相关旧记忆。
3. 模型提出结构化经历与状态建议，附原文依据。
4. 代码检查角色、来源、核心约束、自然遗忘排除、版本和幂等。
5. 状态更新与记忆写入任务持久化；异步显式写入 Claude-Mem，失败重试。

提炼在后台运行，不阻塞下一轮对话。自己的台词不是证明用户性格或关系升级的证据。假设、引用、玩笑和角色扮演需结合语境判断，后续否认要能修正理解。

建议应用侧控制提炼规则，Claude-Mem 负责记忆存储与检索，避免默认编程观察者并行生成重复内容。

## 检索流程

```text
当前消息＋近期上下文＋当前场景
→ 角色范围约束
→ 关键词与语义候选
→ 合并、去重、权限与生命周期核验
→ 相关性筛选与预算控制
→ 仅加入当前回答所需片段
```

- 关键词用于人名、日期、事件名等准确匹配；向量检索匹配语义相近的不同表达。
- “她后来怎样了”等指代要结合近期人物，不能只检索最后一句。
- 无可靠结果可返回零条，不凑固定数量。
- 核心人设固定加入；详细世界观走知识检索；当前角色状态以最新有效记录为准。
- 深度回忆才展开时间线与详情，日常回复避免多次工具往返。
- 后台检索命中不视为用户真实重访，不刷新遗忘计时。

## 建议参数，未确认

候选每路 20 条、最终 8 条／2,000 token，召回超时 2 秒，多语言向量模型 multilingual-e5-small；均需中文样例验证后决定。检索排名与最终相关性阈值不能只靠数字选满。

## 待定

- M-01：固定版本的服务器接口、显式写入、语义检索、更新与删除是否确实可用；历史检查提交仅为候选，不是已测通过的依赖。
- M-02：经历粒度、重复合并、混合检索融合、分数阈值、片段预算和质量集。
- 记忆正文和业务登记的一致性恢复方式，避免部分成功时串状态。
- 取消回复、编辑消息、重新生成的版本如何影响已处理经历，联动 C-03。

## 验收示例

保存“别频繁催我”后，“我不喜欢被督促”能找到相关内容；查询无关话题不加入。重复请求不重复生成记忆。后续澄清可修正旧误解。任何角色不能通过 ID、搜索或时间线读取另一角色记忆。
