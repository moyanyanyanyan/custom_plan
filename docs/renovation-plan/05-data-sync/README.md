# 数据存储、迁移与离线同步

[返回入口](../README.md)

## 已确认

- 采用 PostgreSQL 方向，用户本机没有单独安装 PostgreSQL，需支持 Docker。
- Windows 与安卓先在同一局域网同步。
- 电脑关机、睡眠或平板离线时继续本地操作，重连同步。
- 同步全部现有业务数据：任务、卡牌、道具、史莱姆和共享范围的外观资料。
- 同记录冲突保留双方内容供选择，不静默覆盖。
- 角色外观按角色保存；个人计划与收藏独立于角色。

## 建议存储分工

| 位置 | 内容 |
|---|---|
| 各客户端 SQLite | 可离线操作的业务副本、聊天、待同步队列、游标与冲突 |
| 各客户端私有资源目录 | 头像、壁纸、下载附件 |
| 电脑 PostgreSQL 业务库 | 汇总记录、角色状态、原始聊天、处理任务与来源登记 |
| Claude-Mem 专用库 | 经历内容与检索数据，由其服务管理 |
| 电脑资源持久化卷 | 图片与原始文档，不把大文件塞进同步 JSON |

SQLite 是应用内嵌数据库文件，平板无需另装数据库服务。保存到应用私有目录无需索取整个文件系统权限；卸载或清除数据会删除本地文件，未同步状态必须可见。

## 同步建议

- 本地修改和待同步操作在同一事务提交，界面先响应本地保存。
- 每个操作唯一 ID，携带基础版本；服务端去重，返回确认或冲突。
- 增量拉取采用服务端游标，与业务写入事务协调，避免并发漏事件。
- 删除业务记录使用删除标记，防止离线旧副本复活；这与用户删除角色记忆不是同一权限。
- 冲突记录展示本地与远端内容，选择结果基于最新版本提交。
- 上传资源按内容哈希去重，资源存在后再确认引用，失败可重试。
- 同一应用的头像和面板使用同一数据层，不让多个 WebView 各写一份状态。
- 系统密钥、窗口位置、权限、提醒投递状态按设备保存；任务提醒时间可以同步。
- 显示已保存本机／待同步／已同步／冲突／失败，不把本机保存说成同步完成。

## 迁移建议

1. 备份 state.json 和资源目录，检查当前格式。
2. 事务导入 SQLite，保留 ID、日期、排序与关联，拆分角色／通用／设备设置。
3. 校验记录与资源数量、哈希和引用；失败保留原数据。
4. 成功后切换本地仓库，原 JSON 留作备份，不长期双写。
5. 将电脑数据幂等初始化到空 PostgreSQL 工作空间。
6. 新平板配对下载真实数据，不将演示种子上传合并。

## 待定

- D-01：实体表、操作粒度、字段级还是记录级冲突；重复任务和每日卡牌／道具的多端唯一规则；史莱姆与任务的原子更新。
- D-02：已有用户名与头像如何迁入用户／首个角色；多端已有真实数据的首次合并；密钥保护；备份一致性与回退后新增数据处理。
- SQLite 驱动、服务端数据库工具、轮询或推送、日志保留周期与压缩均为技术建议未定。
- 聊天原始数据与角色状态要同步到哪些客户端、可见范围和缓存容量。

## 验收

迁移可重复、不中途丢数据；两端断网重启后修改仍在；同记录冲突可选择；重复任务及领取不重复；图片同步正确；角色切换不改个人任务；密钥不进入普通同步载荷。
