# 平台适配、窗口与权限

[返回入口](../README.md)

## 已确认

- 支持 Windows 与安卓，重点适配小米平板 8。
- 屏幕侧边悬浮头像，点击展开可操作面板，收起后继续使用下方应用。
- 悬浮入口恢复上次页面；安卓首轮以任务与外观为主。
- 未来支持用户主动授权后采集屏幕，作为独立能力验证。

## 建议方案

- 保留 React + Tauri，共用业务界面；Windows 使用 Rust／系统窗口能力，Android 原生插件处理系统权限与窗口。
- 区分运行环境与能力：Tauri 原生不等于 Windows。桌面多窗口、窗口拖动、单实例和 schtasks 不能直接迁入安卓。
- 安卓普通应用页面作为基础入口；额外实现悬浮头像与面板，不依赖 HyperOS 自带小窗尺寸。
- 头像不抢输入焦点；展开面板可输入，收起恢复焦点。处理导航栏、键盘、旋转、分屏及显示缩放。
- 悬浮窗授权与屏幕采集授权分别获取；屏幕查看、云端分析和长期保存的含义分别说明。
- 使用 MediaProjection 等系统采集能力；会话被系统停止后不得用过期授权静默重启。
- 不为当前需求索取无障碍、摄像头或麦克风权限。
- 系统关闭或清理后如无法常驻，明确展示状态并提供手动恢复，不承诺永久后台存活。

## 待定与验证

- P-01：真机系统版本、后台电池策略与测试时长。
- P-02：悬浮面板用何种原生承载并如何复用共享业务；适当的前台服务类型、通知、启动／停止条件必须真机验证，不能只靠“开服务”保证存活。
- P-03：采集单应用还是全屏；是否临时隐藏自身悬浮层；分辨率、采样间隔、黑屏处理与耗电目标。
- Windows 采集目标选择、锁屏／休眠行为与受保护内容处理。
- 安卓定时提醒属于后续平台适配，先明确不支持状态，不能继续调用 Windows 命令。

## 验收场景

权限同意／拒绝／撤销，键盘弹出，横竖屏，切换应用，面板反复收起展开，系统停止服务，锁屏，任务重启保留。未完成真机测试前不宣称适配完成。
