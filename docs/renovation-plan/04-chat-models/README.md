# 聊天、模型调用与主动陪伴

[返回入口](../README.md)

## 已确认目标

- 角色聊天支持图片输入，并能结合人设、世界观、记忆和个人计划交流。
- 每轮回复后提交记忆提炼，不等待整段会话结束。
- 后续在屏幕授权有效时支持主动聊天，用户最初提出随机 10 秒～5 分钟；精确调度与消息策略还需讨论。
- 云服务器暂不租赁，应用后端先运行在电脑；云端模型 API 与租云服务器是两种不同费用。

## 建议职责

- 聊天调用：理解当前事件、形成临时情绪与表达、流式返回回复。
- 提炼调用：从已结束轮次提出经历及角色状态更新建议，具体规则见 [记忆模块](../03-memory/README.md)。
- 视觉调用：读用户图片和已授权屏幕样本，不把生图能力等同于识图能力。
- Embedding：将资料和记忆转成可检索向量，不承担生成回复。
- 不需要为情绪理解、关系和表达分别串行调用多个模型；先按两条主要路径验证。

## 上下文

```text
核心人设与核心世界规则
＋当前可塑性格、关系与情绪概括
＋近期对话、当前场景
＋相关经历、用户认知
＋相关世界观／知识片段
＋按需读取的真实任务状态
```

核心设定常驻，详细内容检索。超过模型预算时优先移除低相关资料和较早对话，不能静默截断当前输入或重要核心规则。长会话摘要仅是会话上下文，不自动等同永久记忆。

所有检索数据都是资料，不赋予修改核心设定、执行工具或覆盖权限的权力。聊天中产生任务建议后由明确操作写入原计划系统，不凭截图自动完成任务。

## 主动聊天建议

- 设备端检查有效授权与活动状态，取近期画面，再请求角色回复；不持续上传视频。
- 随机间隔指触发时间，实际消息出现还需模型与网络耗时。
- 当前请求未完成时不并行堆积主动消息；暂停后不补发积压消息。
- 两端同时在线时需明确活动设备，避免同时打扰。
- 授权结束、锁屏导致采集停止、角色切换和网络中断都要正确停止或降级。

## 待定

- C-01：供应商、模型名称、视觉清晰度、上下文窗口、结构化输出、延迟和预算。既有接口可复用多少需要验证。
- C-02：随机分布、每次触发是否必说、用户输入时是否延后、每日上限、采样频率和活动设备选择。
- C-03：会话创建与历史、回复取消、消息编辑重生、失败重试、两端同时聊天的生成顺序；前台临时态度与后台状态版本一致性。
- 电脑不可达时是否允许客户端直连模型、密钥如何配置；不要把本地可用计划等同为离线 AI 一定可用。
- token 分配和耗时目标属于建议参数，模型选定前不承诺固定速度。

## 验收

回复不串角色，关闭或取消后不插入错误会话；视觉输入可控；流式失败可见；没有记忆或后端不可用时明确降级；主动消息不重复积压；费用能按调用类型核对。
