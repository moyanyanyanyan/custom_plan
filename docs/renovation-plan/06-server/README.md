# 电脑托管、Docker 与服务通信

[返回入口](../README.md)

## 已确认

- 先用 Windows 电脑运行服务，不租云服务器。
- 平板首先只需与电脑在同一局域网通信。
- 支持 Docker，电脑不需要另装 PostgreSQL。
- 电脑关机或睡眠时服务不可达；本地计划仍可用，待处理数据重连补传。

## 建议部署

```text
Docker Compose
├─ 应用 API／后台任务
├─ PostgreSQL：业务库与记忆专用库
├─ Claude-Mem 服务
├─ Claude-Mem 实际需要的后台进程／Valkey
└─ 数据、资源、配置持久化卷
```

固定镜像／源码版本，不能只用 latest。Claude-Mem 历史检查的服务端基于 PostgreSQL 和 BullMQ／Valkey；真正接入时需核对固定版本，不为未使用能力额外运行生成链路。

- 平板只访问 API，PostgreSQL 不发布到局域网。
- API 做设备配对、用户角色校验和输入限制，不能因在家中网络就省略身份校验。
- 建议 HTTPS 与首次配对核对证书；具体方案待定，禁止无条件关闭证书校验。
- 防火墙仅允许需要的专用网络／本地子网。
- 数据用命名卷；停止服务与删除卷分开，日常命令不删数据。
- 健康检查后才执行迁移、开放 API；服务重启应可恢复后台任务。
- 配置示例不包含真实密钥；日志不能打印模型密钥、配对令牌或整段敏感聊天。
- 备份业务库、记忆库与资源，恢复时先核验自然遗忘排除和处理版本，再提供召回。

## 通信边界

| 通道 | 责任 |
|---|---|
| 前端 → 原生层 | 本地保存、窗口、权限与系统操作 |
| 客户端 → 应用 API | 聊天、同步、角色资料和记忆查看 |
| 应用 → Claude-Mem | 显式写入、检索、生命周期维护 |
| 应用 → 模型服务 | 聊天、提炼、视觉与必要的向量处理 |

存储模块决定怎样合并业务记录；本模块决定服务怎样运行和被安全找到，两者不重复维护同步规则。
