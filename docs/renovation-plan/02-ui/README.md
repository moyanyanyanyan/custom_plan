# UI、角色入口与计划融合

[返回入口](../README.md)

## 已确认布局

```text
现有主面板
├─ 当前角色头像：点击后下方内容替换为角色头像网格
│  └─ 所有头像最后一项：＋创建角色
├─ 主内容：[聊天] [计划]
├─ 右上角设置：[角色设置] [系统设置]
└─ 原发明卡牌入口改为记忆
   ├─ [角色记忆管理]
   └─ [记忆卡牌] → 卡牌／道具
```

- 保留现有计划面板，不额外添加独立首页。
- 所有角色能读取同一份个人计划；这不意味着它们能读取彼此经历或聊天。
- 角色切换影响头像、名字、壁纸、对话与角色状态。
- 卡牌和道具为个人收藏，切换角色不改变，现有卡牌业务包含在记忆卡牌页内。

## 设置

| 内容 | 角色设置 | 系统设置 |
|---|---|---|
| 范围 | 当前角色 | 不随角色变化 |
| 字段 | 头像、名称、核心人设、核心世界观、角色壁纸 | API Key、模型服务与其他系统配置 |
| 建议识别方式 | 角色小头像、角色名、“仅此角色” | 固定齿轮、中性底色、“不随角色切换” |

建议两页独立保存和恢复默认，未保存时切换需处理草稿。系统范围还需区分跨设备配置与本机权限、窗口位置、密钥，不混为“全量同步”。

## 角色记忆查看

用户明确要求包含五类：非核心性格、非核心世界观、对用户的认知、经历记忆、对用户的情感与关系。

建议小窗使用五个折叠分区，详情页在同一容器内导航。核心设定链接回角色设置，不复制第二份编辑器。用户不能手动删除相关记忆；自然遗忘的细节不在查看页重新展示。

## 建议交互

- 角色头像网格带名称、当前标记和返回；取消恢复原页面，选中后恢复聊天／计划位置。
- 输入草稿按角色保存。后台回复固定归属原角色，不随界面切换串入新角色。
- 聊天生成任务建议后由用户确认写入原计划系统；查看任务可带摘要去聊天。
- 开启屏幕陪伴后持续显示状态与停止入口；切换角色不静默转移屏幕查看。
- 沿用现有主题，正文增加稳定底色；触控区域、文本字号按安卓重新适配。
- 情绪关系用文字与原因呈现，不默认显示单一好感度。

## 待定

- U-01：主头像替换为角色后，现有用户名、身份和今日进度怎样排列；首次打开聊天还是计划；最终线框图。
- U-02：创建步骤、必填项、初始角色关系、数量上限；切换角色对进行中的陪伴如何处理。角色生命周期操作另行讨论，不推断允许清空相关记忆。
- U-03：用户是否能直接纠正非核心状态；目前明确的是不能删除，不能自行扩大为可编辑全部记忆。聊天澄清仍需系统理解。内在情感与推测展示多少待定。
- 聊天历史、关闭生成、设置草稿和安卓返回栈详细规则。

## 验收

切换角色不改变个人任务与收藏；设置保存对象明确；返回和收起不丢草稿；记忆页没有删除或共享能力；冷静型角色不被统一视觉文案强行表现为热情型。
